Tools & Function Calling

Typed tools, external systems and safe execution.

PythonAlgorithmArchitecture

1. Understand the idea

The model may request that your application call a tool. Your code decides whether and how to execute it.

Analogy: Treat this as a station on an assembly line: a clear input arrives, a defined transformation happens, and a verifiable output leaves.

2. Algorithm in plain English

  1. Model sees tool schema
  2. emits tool call
  3. validate permissions
  4. execute
  5. return tool result.

3. Architecture / data-flow diagram

Human request
→
Model chooses tool
→
Application validates
→
Tool executes
→
Model final answer

4. Concepts and syntax explained

Tool schema

Name, description and validated input arguments.

Tool call

Structured model request to invoke named functionality.

Execution boundary

Your app executes tools; models do not receive blanket authority.

Allowlist

Expose only tools required for the task.

Side effects

Require authorization and confirmation for destructive actions.

Idempotency

Avoid duplicate financial, external or deployment operations on retry.

5. Working Python example

Copy this snippet into a Python file. Run the setup from the course home page first. Examples that call a hosted model require a valid API key and network connection; the HTML site itself does not.

Python · example
from langchain.tools import tool
from langchain.agents import create_agent
@tool
def multiply(a: int, b: int) -> int:
    """Multiply two whole numbers."""
    return a * b
agent = create_agent(model="openai:gpt-4.1-mini", tools=[multiply])
result = agent.invoke({"messages":[{"role":"user","content":"What is 13 times 7?"}]})
print(result["messages"][-1].content)

6. Trace the execution

Read the code from top to bottom: imports resolve the declared interfaces; configuration builds a reusable component; invocation passes application data into the algorithm; the final statement inspects or prints the result. For production work, add input validation, failure handling and observability at the integration boundary.

7. Common mistakes

  • Following older tutorials without checking package versions or changed imports.
  • Confusing model-generated text with trusted, validated application data.
  • Ignoring security, latency, token costs, concurrency and failure handling.
  • Assuming the locally browsable tutorial can itself run remote Python code.
