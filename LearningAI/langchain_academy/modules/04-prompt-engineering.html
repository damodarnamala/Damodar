Prompt Engineering

Templates, placeholders, instructions and few-shot.

PythonAlgorithmArchitecture

1. Understand the idea

Templates separate stable instructions from runtime data. Use explicit delimiters for untrusted content.

Analogy: Treat this as a station on an assembly line: a clear input arrives, a defined transformation happens, and a verifiable output leaves.

2. Algorithm in plain English

  1. Define template
  2. bind named fields
  3. format messages
  4. invoke model.

4. Concepts and syntax explained

Template variables

Values replaced at runtime; missing values generally raise errors.

Few-shot

Give a small number of representative demonstrations.

Message placeholders

Inject existing messages such as conversation history.

Prompt injection

User or retrieved text that tries to override trusted instructions.

Instruction hierarchy

Keep system instructions separate from user-provided documents.

Output contract

Specify schema, format and refusal handling explicitly.

5. Working Python example

Copy this snippet into a Python file. Run the setup from the course home page first. Examples that call a hosted model require a valid API key and network connection; the HTML site itself does not.

Python · example
from langchain_core.prompts import ChatPromptTemplate
from langchain.chat_models import init_chat_model
prompt = ChatPromptTemplate.from_messages([
    ("system", "Explain {topic} to a beginner in two sentences."),
    ("human", "Example domain: {domain}")
])
chain = prompt | init_chat_model("openai:gpt-4.1-mini")
print(chain.invoke({"topic":"embeddings", "domain":"music"}).content)

6. Trace the execution

Read the code from top to bottom: imports resolve the declared interfaces; configuration builds a reusable component; invocation passes application data into the algorithm; the final statement inspects or prints the result. For production work, add input validation, failure handling and observability at the integration boundary.

7. Common mistakes

  • Following older tutorials without checking package versions or changed imports.
  • Confusing model-generated text with trusted, validated application data.
  • Ignoring security, latency, token costs, concurrency and failure handling.
  • Assuming the locally browsable tutorial can itself run remote Python code.
