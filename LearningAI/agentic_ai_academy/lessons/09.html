State & checkpoints

Learning outcome: Model agent state and resumable workflows

1. What is it?

State is the structured snapshot of the task at a point in time. Checkpoints persist enough information to resume without repeating irreversible side effects.

2. Why does it matter?

Persist checkpoints at safe boundaries and attach stable operation identifiers to writes.

Concrete scenario: Resume an interrupted workflow. The figure below names the actual components and shows how information moves among them.

3. Key concepts and vocabulary

ConceptExplanation
Stateworkflow data at a point in time

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

5. Step-by-step algorithm

  1. State v1: Process the state v1 stage, and pass its defined output to the next node.
  2. Execute node: Process the execute node stage, and pass its defined output to the next node.
  3. State v2: Process the state v2 stage, and pass its defined output to the next node.
  4. Persist checkpoint: Process the persist checkpoint stage, and pass its defined output to the next node.
  5. Process interrupted: Process the process interrupted stage, and pass its defined output to the next node.
  6. Restore and continue: Emit a result only after verifying the stated conditions.

6. Runnable Python lesson

This module links to 03_memory.py. Some modules reuse an earlier example intentionally: revisit it and identify which concept is newly relevant. The downloadable file is in the examples/ folder.

Run locally: python examples/03_memory.py from the extracted project root. Examples using provider libraries also need the dependencies and credentials explained in Setup.
"""Bounded memory; intentionally no secrets or durable persistence."""
from collections import deque

class ConversationMemory:
    def __init__(self, max_messages: int = 6):
        self.messages = deque(maxlen=max_messages)

    def add(self, role: str, content: str) -> None:
        if role not in ("user", "assistant"):
            raise ValueError("Invalid role")
        self.messages.append({"role": role, "content": content})

    def context(self) -> list[dict[str, str]]:
        return list(self.messages)

if __name__ == "__main__":
    m = ConversationMemory(2)
    m.add("user", "Hello")
    m.add("assistant", "Hi")
    m.add("user", "Again")
    print(m.context())

8. Real-world design exercise

You are building a state & checkpoints capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Persist progress in a local JSON store. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Losing correlation IDs between checkpoints. Mitigation: make this condition explicit in a test or a runtime policy.
  • Using in-memory state for durable workflows. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In persistent state checkpoint sequence, what happens between “Execute node” and “Restore and continue”, and what must be checked?

Follow the labeled arrows in the diagram: Execute node hands a defined result through the intermediate stages toward Restore and continue. For this topic, explicitly guard against losing correlation ids between checkpoints.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.
