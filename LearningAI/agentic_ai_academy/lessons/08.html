MCP: tools, resources and prompts

Learning outcome: Publish standard capabilities using an MCP server

1. What is it?

MCP standardizes how a host accesses tools, resources and prompts published by servers. A tool can cause actions; a resource provides context; a prompt is a reusable template.

2. Why does it matter?

Treat remote MCP servers as trust boundaries. Authenticate and apply least privilege.

Concrete scenario: Discover and call an external capability. The figure below names the actual components and shows how information moves among them.

3. Key concepts and vocabulary

ConceptExplanation
Hostapplication running an agent
Clientprotocol connection owned by host
Serverpublishes tools/resources/prompts
Resourcesreadable context exposed by server

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

5. Step-by-step algorithm

  1. Agent host: Process the agent host stage, and pass its defined output to the next node.
  2. MCP client: Process the mcp client stage, and pass its defined output to the next node.
  3. MCP server: Process the mcp server stage, and pass its defined output to the next node.
  4. Tools listing: Process the tools listing stage, and pass its defined output to the next node.
  5. Tool invocation: Process the tool invocation stage, and pass its defined output to the next node.
  6. Structured result: Emit a result only after verifying the stated conditions.

6. Runnable Python lesson

This module links to 09_mcp_server.py. Some modules reuse an earlier example intentionally: revisit it and identify which concept is newly relevant. The downloadable file is in the examples/ folder.

Run locally: python examples/09_mcp_server.py from the extracted project root. Examples using provider libraries also need the dependencies and credentials explained in Setup.
"""Requires: pip install 'mcp[cli]'. Example for MCP Python SDK v2."""
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("Learning Tools")

@mcp.tool()
def calculate_total(price: float, quantity: int) -> float:
    """Compute a total, with basic argument validation."""
    if price < 0 or quantity < 0:
        raise ValueError("Non-negative values required")
    return round(price * quantity, 2)

@mcp.resource("guide://intro")
def introduction() -> str:
    return "This server offers learning-only arithmetic tools."

if __name__ == "__main__":
    mcp.run()

8. Real-world design exercise

You are building a mcp: tools, resources and prompts capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Implement an MCP FastMCP server. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Equating MCP with an LLM. Mitigation: make this condition explicit in a test or a runtime policy.
  • Trusting arbitrary remote MCP servers. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In mcp host–client–server sequence, what happens between “MCP client” and “Structured result”, and what must be checked?

Follow the labeled arrows in the diagram: MCP client hands a defined result through the intermediate stages toward Structured result. For this topic, explicitly guard against equating mcp with an llm.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.
