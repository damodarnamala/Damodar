AI & LLM foundations

Learning outcome: Understand tokens, models, embeddings, sampling, and structured outputs

1. What is it?

Tokens are pieces of text, not always words. A model predicts tokens based on its context. Embeddings map content into vectors that can be compared mathematically. A structured output contract uses a schema to reject malformed data.

2. Why does it matter?

When an application needs reliable processing, validate model output: generation is probabilistic but schema checks are deterministic.

Concrete scenario: Predict the next tokens in a structured response. The figure below names the actual components and shows how information moves among them.

3. Key concepts and vocabulary

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

5. Step-by-step algorithm

  1. User prompt: Process the user prompt stage, and pass its defined output to the next node.
  2. Tokenizer: Process the tokenizer stage, and pass its defined output to the next node.
  3. Context + embeddings: Process the context + embeddings stage, and pass its defined output to the next node.
  4. Transformer inference: Process the transformer inference stage, and pass its defined output to the next node.
  5. Sampling: Process the sampling stage, and pass its defined output to the next node.
  6. Generated tokens: Emit a result only after verifying the stated conditions.

6. Runnable Python lesson

This module links to 01_agent_loop.py. Some modules reuse an earlier example intentionally: revisit it and identify which concept is newly relevant. The downloadable file is in the examples/ folder.

Run locally: python examples/01_agent_loop.py from the extracted project root. Examples using provider libraries also need the dependencies and credentials explained in Setup.
"""No API key needed. A deterministic agent-like tool loop."""
from dataclasses import dataclass

@dataclass
class Action:
    name: str
    a: float = 0
    b: float = 0

def add(a: float, b: float) -> float:
    return a + b

def run(goal: str, max_steps: int = 3) -> str:
    tools = {"add": add}
    history = []
    for _ in range(max_steps):
        if not history:
            action = Action("add", 12, 30) if goal == "add" else Action("final")
        else:
            return f"Result: {history[-1]}"
        if action.name == "final":
            return "Unsupported request"
        if action.name not in tools:
            raise ValueError("Not allowed")
        history.append(tools[action.name](action.a, action.b))
    raise RuntimeError("Step limit")

if __name__ == "__main__":
    assert run("add") == "Result: 42"
    print(run("add"))

9. Common mistakes and troubleshooting

  • Using temperature as a truthfulness guarantee. Mitigation: make this condition explicit in a test or a runtime policy.
  • Exceeding the context window without pruning. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In llm inference pipeline, what happens between “Tokenizer” and “Generated tokens”, and what must be checked?

Follow the labeled arrows in the diagram: Tokenizer hands a defined result through the intermediate stages toward Generated tokens. For this topic, explicitly guard against using temperature as a truthfulness guarantee.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.
