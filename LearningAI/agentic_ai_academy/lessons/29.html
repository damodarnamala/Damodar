Deployment and operations

Learning outcome: Ship a managed API with observability and rollback plans

1. What is it?

Production systems need persistent state, job ownership, retry discipline, health probes, CI gates and rollback procedures. An HTTP endpoint alone is not a reliable long-running agent architecture.

2. Why does it matter?

Separate incoming requests from durable worker processing for long tasks.

Concrete scenario: Serve an agent using stateful worker infrastructure. The figure below names the actual components and shows how information moves among them.

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

5. Step-by-step algorithm

  1. API gateway: Process the api gateway stage, and pass its defined output to the next node.
  2. FastAPI service: Process the fastapi service stage, and pass its defined output to the next node.
  3. Work queue: Process the work queue stage, and pass its defined output to the next node.
  4. Agent workers: Process the agent workers stage, and pass its defined output to the next node.
  5. PostgreSQL state: Process the postgresql state stage, and pass its defined output to the next node.
  6. Metrics + health: Emit a result only after verifying the stated conditions.

8. Real-world design exercise

You are building a deployment and operations capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Containerize a FastAPI task service. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Assuming HTTP request lifetime equals job lifetime. Mitigation: make this condition explicit in a test or a runtime policy.
  • Deploying stateful agents without persistence. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In deployment topology, what happens between “FastAPI service” and “Metrics + health”, and what must be checked?

Follow the labeled arrows in the diagram: FastAPI service hands a defined result through the intermediate stages toward Metrics + health. For this topic, explicitly guard against assuming http request lifetime equals job lifetime.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.

Hands-on assignment

Modify 10_fastapi.py to log each step as a dictionary containing step, action, status and elapsed_ms. Then write tests for one success case and one rejection case.

Interview angle

Design interview: You need to serve an agent using stateful worker infrastructure. Defend the boundaries between api gateway and metrics + health, describe how to handle “assuming http request lifetime equals job lifetime”, and identify a measurable acceptance test.
