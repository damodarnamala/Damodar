Agent security

Learning outcome: Prevent unauthorized actions and prompt injection attacks

1. What is it?

Prompt injection happens when attacker-controlled content tries to become instructions. The safe boundary is enforced with permissions, isolation, validation and human approval rather than prompting alone.

2. Why does it matter?

Treat documents, webpages, logs and tool outputs as untrusted data.

Concrete scenario: Reject instructions embedded in hostile content. The figure below names the actual components and shows how information moves among them.

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

"""Illustrates approval tied to an exact proposed action digest."""
import hashlib
import json

def digest(action: dict) -> str:
    data = json.dumps(action, sort_keys=True, separators=(",", ":")).encode()
    return hashlib.sha256(data).hexdigest()

class ApprovalGate:
    def __init__(self):
        self.approved = set()

    def authorize(self, action: dict, reviewer: str):
        if not reviewer:
            raise ValueError("Reviewer identity required")
        self.approved.add(digest(action))

    def permitted(self, action: dict) -> bool:
        return digest(action) in self.approved

if __name__ == "__main__":
    gate = ApprovalGate()
    action = {"type": "deploy", "version": "1.0.0"}
    gate.authorize(action, "authorized-reviewer-demo")
    assert gate.permitted(action)
    assert not gate.permitted({**action, "version": "2.0.0"})
    print("Approval is action-specific")

8. Real-world design exercise

You are building a agent security capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Build a command allowlist. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Granting tool output authority over instructions. Mitigation: make this condition explicit in a test or a runtime policy.
  • Sharing production credentials with a coding sandbox. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In security trust boundary flow, what happens between “Untrusted page text” and “Audit trail”, and what must be checked?

Follow the labeled arrows in the diagram: Untrusted page text hands a defined result through the intermediate stages toward Audit trail. For this topic, explicitly guard against granting tool output authority over instructions.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.
