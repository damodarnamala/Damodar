Reusable agent skills

Learning outcome: Package repeatable guidance and scripts

1. What is it?

A skill packages task-specific instructions and optional supporting scripts. A tool performs an action; a skill guides how and when to use capabilities.

2. Why does it matter?

Version skills and test their behavior against representative tasks.

Concrete scenario: Load the relevant skill only when needed. The figure below names the actual components and shows how information moves among them.

3. Key concepts and vocabulary

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

5. Step-by-step algorithm

  1. User task: Process the user task stage, and pass its defined output to the next node.
  2. Skill catalog: Process the skill catalog stage, and pass its defined output to the next node.
  3. Match description: Process the match description stage, and pass its defined output to the next node.
  4. Load skill instructions: Process the load skill instructions stage, and pass its defined output to the next node.
  5. Invoke approved tool: Process the invoke approved tool stage, and pass its defined output to the next node.
  6. Check result: Emit a result only after verifying the stated conditions.

6. Runnable Python lesson

This module links to 02_tool_registry.py. Some modules reuse an earlier example intentionally: revisit it and identify which concept is newly relevant. The downloadable file is in the examples/ folder.

Run locally: python examples/02_tool_registry.py from the extracted project root. Examples using provider libraries also need the dependencies and credentials explained in Setup.
"""Validated tool registry using only Python standard library."""
from dataclasses import dataclass
from collections.abc import Callable

@dataclass(frozen=True)
class ToolSpec:
    name: str
    fn: Callable[[int, int], int]

def multiply(a: int, b: int) -> int:
    return a * b

REGISTRY = {"multiply": ToolSpec("multiply", multiply)}

def execute(name: str, arguments: dict) -> int:
    if name not in REGISTRY:
        raise PermissionError("Unknown or prohibited tool")
    if set(arguments) != {"a", "b"} or any(type(v) is not int for v in arguments.values()):
        raise ValueError("Arguments must be integer a and b")
    return REGISTRY[name].fn(**arguments)

if __name__ == "__main__":
    print(execute("multiply", {"a": 6, "b": 7}))

8. Real-world design exercise

You are building a reusable agent skills capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Create a code-review skill. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Loading every skill into each prompt. Mitigation: make this condition explicit in a test or a runtime policy.
  • Treating skill instructions as unrestricted authority. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In skill discovery and activation, what happens between “Skill catalog” and “Check result”, and what must be checked?

Follow the labeled arrows in the diagram: Skill catalog hands a defined result through the intermediate stages toward Check result. For this topic, explicitly guard against loading every skill into each prompt.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.
