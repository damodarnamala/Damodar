Framework selection

Learning outcome: Compare portability and control across ecosystems

1. What is it?

Different frameworks make different trade-offs in flexibility, ergonomics, durable execution and ecosystem integration. A framework comparison must use the same benchmark tasks.

2. Why does it matter?

Keep business rules independent of framework imports to reduce lock-in.

Concrete scenario: Choose an implementation based on requirements. The figure below names the actual components and shows how information moves among them.

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

6. Runnable Python lesson

This module links to 06_openai_agents.py. Some modules reuse an earlier example intentionally: revisit it and identify which concept is newly relevant. The downloadable file is in the examples/ folder.

Run locally: python examples/06_openai_agents.py from the extracted project root. Examples using provider libraries also need the dependencies and credentials explained in Setup.
"""Requires: pip install openai-agents and OPENAI_API_KEY."""
from agents import Agent, Runner, function_tool

@function_tool
def get_shipping_fee(country: str) -> str:
    """Return demonstration shipping fees for a country."""
    return {"India": "₹100", "USA": "$10"}.get(country, "Unknown")

agent = Agent(
    name="Shipping Assistant",
    instructions="Help with demo shipping fee questions. Use the tool for prices.",
    tools=[get_shipping_fee],
)

if __name__ == "__main__":
    result = Runner.run_sync(agent, "What is the shipping fee for India?")
    print(result.final_output)

8. Real-world design exercise

You are building a framework selection capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Draft an architecture decision record. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Choosing frameworks from popularity alone. Mitigation: make this condition explicit in a test or a runtime policy.
  • Ignoring operational observability. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In framework selection decision tree, what happens between “Simple custom loop?” and “Prototype + benchmark”, and what must be checked?

Follow the labeled arrows in the diagram: Simple custom loop? hands a defined result through the intermediate stages toward Prototype + benchmark. For this topic, explicitly guard against choosing frameworks from popularity alone.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.
