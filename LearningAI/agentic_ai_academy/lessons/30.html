Governance & AI software factory

Learning outcome: Orchestrate Jira-to-production with explicit gates

1. What is it?

An AI software factory maps a Jira ticket into requirements, design, changes, tests, pull requests, approved releases and observability. A release is a controlled transaction, not a model-generated command.

2. Why does it matter?

Require independent security checks and approval for deployment; preserve an audit trail.

Concrete scenario: Take a Jira issue to a controlled release. The figure below names the actual components and shows how information moves among them.

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

5. Step-by-step algorithm

  1. Jira requirement: Process the jira requirement stage, and pass its defined output to the next node.
  2. Plan + architecture: Process the plan + architecture stage, and pass its defined output to the next node.
  3. Sandbox code patch: Process the sandbox code patch stage, and pass its defined output to the next node.
  4. CI / test / scan: Process the ci / test / scan stage, and pass its defined output to the next node.
  5. Human merge approval: Process the human merge approval stage, and pass its defined output to the next node.
  6. Release + monitor: Emit a result only after verifying the stated conditions.

"""Illustrates approval tied to an exact proposed action digest."""
import hashlib
import json

def digest(action: dict) -> str:
    data = json.dumps(action, sort_keys=True, separators=(",", ":")).encode()
    return hashlib.sha256(data).hexdigest()

class ApprovalGate:
    def __init__(self):
        self.approved = set()

    def authorize(self, action: dict, reviewer: str):
        if not reviewer:
            raise ValueError("Reviewer identity required")
        self.approved.add(digest(action))

    def permitted(self, action: dict) -> bool:
        return digest(action) in self.approved

if __name__ == "__main__":
    gate = ApprovalGate()
    action = {"type": "deploy", "version": "1.0.0"}
    gate.authorize(action, "authorized-reviewer-demo")
    assert gate.permitted(action)
    assert not gate.permitted({**action, "version": "2.0.0"})
    print("Approval is action-specific")

8. Real-world design exercise

You are building a governance & ai software factory capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Design a production-ready AI software factory. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Skipping release approval because tests pass. Mitigation: make this condition explicit in a test or a runtime policy.
  • Equating merged code with production readiness. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In ai software factory deployment gates, what happens between “Plan + architecture” and “Release + monitor”, and what must be checked?

Follow the labeled arrows in the diagram: Plan + architecture hands a defined result through the intermediate stages toward Release + monitor. For this topic, explicitly guard against skipping release approval because tests pass.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.
