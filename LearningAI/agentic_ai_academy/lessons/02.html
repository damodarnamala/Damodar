What makes an AI agent?

Learning outcome: Understand goals, observations, actions, autonomy and bounded execution

1. What is it?

An agent is a bounded decision-making process that repeatedly observes context, selects an action, receives feedback, and either continues or produces a result. A workflow has predefined paths; an agent can choose its next step within permitted constraints.

2. Why does it matter?

Use an agent when the next appropriate step depends on information not known in advance. Use an ordinary function or workflow when the path is predictable.

Concrete scenario: Resolve an unknown fact with an authorized tool. The figure below names the actual components and shows how information moves among them.

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

5. Step-by-step algorithm

  1. New goal: Process the new goal stage, and pass its defined output to the next node.
  2. Choose response or tool: Process the choose response or tool stage, and pass its defined output to the next node.
  3. Call approved tool: Process the call approved tool stage, and pass its defined output to the next node.
  4. Read observation: Process the read observation stage, and pass its defined output to the next node.
  5. Goal satisfied?: Process the goal satisfied? stage, and pass its defined output to the next node.
  6. Return answer: Emit a result only after verifying the stated conditions.

6. Runnable Python lesson

This module links to 01_agent_loop.py. Some modules reuse an earlier example intentionally: revisit it and identify which concept is newly relevant. The downloadable file is in the examples/ folder.

Run locally: python examples/01_agent_loop.py from the extracted project root. Examples using provider libraries also need the dependencies and credentials explained in Setup.
"""No API key needed. A deterministic agent-like tool loop."""
from dataclasses import dataclass

@dataclass
class Action:
    name: str
    a: float = 0
    b: float = 0

def add(a: float, b: float) -> float:
    return a + b

def run(goal: str, max_steps: int = 3) -> str:
    tools = {"add": add}
    history = []
    for _ in range(max_steps):
        if not history:
            action = Action("add", 12, 30) if goal == "add" else Action("final")
        else:
            return f"Result: {history[-1]}"
        if action.name == "final":
            return "Unsupported request"
        if action.name not in tools:
            raise ValueError("Not allowed")
        history.append(tools[action.name](action.a, action.b))
    raise RuntimeError("Step limit")

if __name__ == "__main__":
    assert run("add") == "Result: 42"
    print(run("add"))

9. Common mistakes and troubleshooting

  • Treating a chatbot response as an action. Mitigation: make this condition explicit in a test or a runtime policy.
  • Allowing unlimited agent iterations. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In agent decision-cycle activity, what happens between “Choose response or tool” and “Return answer”, and what must be checked?

Follow the labeled arrows in the diagram: Choose response or tool hands a defined result through the intermediate stages toward Return answer. For this topic, explicitly guard against treating a chatbot response as an action.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.
