Enterprise agent architecture

Learning outcome: Apply clean boundaries to orchestration and integrations

1. What is it?

Agent orchestration is an application service, while domain logic and security policy belong in independent business modules. Adapters translate between tools, databases, model providers and internal contracts.

2. Why does it matter?

Define bounded contexts before building a large “agent manager” object.

Concrete scenario: Separate business orchestration from integrations. The figure below names the actual components and shows how information moves among them.

3. Key concepts and vocabulary

ConceptExplanation
Portstable domain-facing interface
Adapterconcrete external integration
Domain policycore business rule
Fault boundaryisolated failure domain

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

5. Step-by-step algorithm

  1. Inbound API: Process the inbound api stage, and pass its defined output to the next node.
  2. Application service: Process the application service stage, and pass its defined output to the next node.
  3. Domain policy: Process the domain policy stage, and pass its defined output to the next node.
  4. Tool port: Process the tool port stage, and pass its defined output to the next node.
  5. Adapter: external API: Process the adapter: external api stage, and pass its defined output to the next node.
  6. State repository: Emit a result only after verifying the stated conditions.

8. Real-world design exercise

You are building a enterprise agent architecture capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Design ports/adapters for a tool gateway. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Mixing HTTP handling with agent decisions. Mitigation: make this condition explicit in a test or a runtime policy.
  • Letting tool adapters bypass policy. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In hexagonal architecture component view, what happens between “Application service” and “State repository”, and what must be checked?

Follow the labeled arrows in the diagram: Application service hands a defined result through the intermediate stages toward State repository. For this topic, explicitly guard against mixing http handling with agent decisions.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.

Hands-on assignment

Modify 10_fastapi.py to log each step as a dictionary containing step, action, status and elapsed_ms. Then write tests for one success case and one rejection case.

Interview angle

Design interview: You need to separate business orchestration from integrations. Defend the boundaries between inbound api and state repository, describe how to handle “mixing http handling with agent decisions”, and identify a measurable acceptance test.
