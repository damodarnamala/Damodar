Python for agents

Learning outcome: Use types, dataclasses, async, errors and testable interfaces

1. What is it?

Agent applications are mostly ordinary software: schemas, adapters, error handling and async operations. Async speeds up independent I/O but does not magically parallelize CPU-heavy model inference.

2. Why does it matter?

Prefer typed interfaces and injectable dependencies; mock external services in tests.

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

5. Step-by-step algorithm

  1. Main coroutine: Process the main coroutine stage, and pass its defined output to the next node.

  3. Fetch A: Process the fetch a stage, and pass its defined output to the next node.
  4. Fetch B: Process the fetch b stage, and pass its defined output to the next node.
  5. Merge typed results: Process the merge typed results stage, and pass its defined output to the next node.
  6. Handle exceptions: Emit a result only after verifying the stated conditions.

6. Runnable Python lesson

This module links to 05_retries.py. Some modules reuse an earlier example intentionally: revisit it and identify which concept is newly relevant. The downloadable file is in the examples/ folder.

Run locally: python examples/05_retries.py from the extracted project root. Examples using provider libraries also need the dependencies and credentials explained in Setup.
"""Retry transient errors only; do not retry non-idempotent writes blindly."""
import time

def retry(operation, attempts: int = 3, delay: float = 0.01):
    for index in range(attempts):
        try:
            return operation()
        except ConnectionError:
            if index == attempts - 1:
                raise
            time.sleep(delay * (2 ** index))

if __name__ == "__main__":
    calls = [0]
    def flaky():
        calls[0] += 1
        if calls[0] < 3:
            raise ConnectionError("transient")
        return "success"
    print(retry(flaky))

8. Real-world design exercise

You are building a python for agents capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Implement an asynchronous tool runner. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Blocking an async event loop. Mitigation: make this condition explicit in a test or a runtime policy.
  • Swallowing exceptions without recording them. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In async python task lifecycle, what happens between “asyncio.gather” and “Handle exceptions”, and what must be checked?

Follow the labeled arrows in the diagram: asyncio.gather hands a defined result through the intermediate stages toward Handle exceptions. For this topic, explicitly guard against blocking an async event loop.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.
