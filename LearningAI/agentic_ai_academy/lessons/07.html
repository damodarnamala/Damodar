Tools and function calling

Learning outcome: Define tool contracts and validate each call

1. What is it?

A tool is a function exposed through a documented schema. The model supplies arguments; code validates type, authorization and side effects before calling the function.

2. Why does it matter?

Never map unvalidated model text directly to shell commands or unrestricted URLs.

Concrete scenario: Execute a calculator action safely. The figure below names the actual components and shows how information moves among them.

3. Key concepts and vocabulary

ConceptExplanation
Tool schemacontract for named arguments

Idempotencyrepeated calls do not duplicate side effects

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

6. Runnable Python lesson

This module links to 02_tool_registry.py. Some modules reuse an earlier example intentionally: revisit it and identify which concept is newly relevant. The downloadable file is in the examples/ folder.

Run locally: python examples/02_tool_registry.py from the extracted project root. Examples using provider libraries also need the dependencies and credentials explained in Setup.
"""Validated tool registry using only Python standard library."""
from dataclasses import dataclass
from collections.abc import Callable

@dataclass(frozen=True)
class ToolSpec:
    name: str
    fn: Callable[[int, int], int]

def multiply(a: int, b: int) -> int:
    return a * b

REGISTRY = {"multiply": ToolSpec("multiply", multiply)}

def execute(name: str, arguments: dict) -> int:
    if name not in REGISTRY:
        raise PermissionError("Unknown or prohibited tool")
    if set(arguments) != {"a", "b"} or any(type(v) is not int for v in arguments.values()):
        raise ValueError("Arguments must be integer a and b")
    return REGISTRY[name].fn(**arguments)

if __name__ == "__main__":
    print(execute("multiply", {"a": 6, "b": 7}))

8. Real-world design exercise

You are building a tools and function calling capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Implement safe tool calling. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Calling tools directly from unvalidated JSON. Mitigation: make this condition explicit in a test or a runtime policy.
  • Retrying write actions without idempotency keys. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In tool-call sequence, what happens between “JSON schema validation” and “Model continuation”, and what must be checked?

Follow the labeled arrows in the diagram: JSON schema validation hands a defined result through the intermediate stages toward Model continuation. For this topic, explicitly guard against calling tools directly from unvalidated json.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.
