OpenAI Agents SDK

Learning outcome: Create agents and specialist handoffs with a managed loop

1. What is it?

The OpenAI Agents SDK provides Agent definitions, Runner execution, tools, handoffs and tracing. The Runner handles the model/tool loop under your configured limits and policies.

2. Why does it matter?

Use specialized agents only when boundaries and ownership are well-defined.

Concrete scenario: Route specialist work to a second agent. The figure below names the actual components and shows how information moves among them.

3. Key concepts and vocabulary

ConceptExplanation
Runnerorchestrates agent execution
Agentinstructions, model and available tools
Handofftransfers control to another agent
Tracingrecords agent and tool operations

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

5. Step-by-step algorithm

  1. Runner.run: Process the runner.run stage, and pass its defined output to the next node.
  2. Triage agent: Process the triage agent stage, and pass its defined output to the next node.
  3. Handoff decision: Process the handoff decision stage, and pass its defined output to the next node.
  4. Specialist agent: Process the specialist agent stage, and pass its defined output to the next node.
  5. Tool invocation: Process the tool invocation stage, and pass its defined output to the next node.
  6. Final output: Emit a result only after verifying the stated conditions.

6. Runnable Python lesson

This module links to 06_openai_agents.py. Some modules reuse an earlier example intentionally: revisit it and identify which concept is newly relevant. The downloadable file is in the examples/ folder.

Run locally: python examples/06_openai_agents.py from the extracted project root. Examples using provider libraries also need the dependencies and credentials explained in Setup.
"""Requires: pip install openai-agents and OPENAI_API_KEY."""
from agents import Agent, Runner, function_tool

@function_tool
def get_shipping_fee(country: str) -> str:
    """Return demonstration shipping fees for a country."""
    return {"India": "₹100", "USA": "$10"}.get(country, "Unknown")

agent = Agent(
    name="Shipping Assistant",
    instructions="Help with demo shipping fee questions. Use the tool for prices.",
    tools=[get_shipping_fee],
)

if __name__ == "__main__":
    result = Runner.run_sync(agent, "What is the shipping fee for India?")
    print(result.final_output)

8. Real-world design exercise

You are building a openai agents sdk capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Create a single agent with a tool. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Using unverified SDK examples. Mitigation: make this condition explicit in a test or a runtime policy.
  • Mistaking handoffs for parallel execution. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In openai agents sdk handoff sequence, what happens between “Triage agent” and “Final output”, and what must be checked?

Follow the labeled arrows in the diagram: Triage agent hands a defined result through the intermediate stages toward Final output. For this topic, explicitly guard against using unverified sdk examples.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.
