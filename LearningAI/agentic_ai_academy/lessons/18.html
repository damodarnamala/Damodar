Multi-agent collaboration

Learning outcome: Coordinate specialists without uncontrolled delegation

1. What is it?

Multi-agent systems split a problem across specialized workers, but coordination introduces latency, conflicting conclusions and harder debugging. Delegation needs an owner and a finish condition.

2. Why does it matter?

Start with one agent; add specialists only when evidence shows meaningful benefits.

Concrete scenario: Delegate research and verification to specialists. The figure below names the actual components and shows how information moves among them.

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

5. Step-by-step algorithm

  1. Supervisor: Process the supervisor stage, and pass its defined output to the next node.
  2. Research worker: Process the research worker stage, and pass its defined output to the next node.
  3. Code worker: Process the code worker stage, and pass its defined output to the next node.
  4. Reviewer: Process the reviewer stage, and pass its defined output to the next node.
  5. Shared artifacts: Process the shared artifacts stage, and pass its defined output to the next node.
  6. Final synthesis: Emit a result only after verifying the stated conditions.

"""Illustrates approval tied to an exact proposed action digest."""
import hashlib
import json

def digest(action: dict) -> str:
    data = json.dumps(action, sort_keys=True, separators=(",", ":")).encode()
    return hashlib.sha256(data).hexdigest()

class ApprovalGate:
    def __init__(self):
        self.approved = set()

    def authorize(self, action: dict, reviewer: str):
        if not reviewer:
            raise ValueError("Reviewer identity required")
        self.approved.add(digest(action))

    def permitted(self, action: dict) -> bool:
        return digest(action) in self.approved

if __name__ == "__main__":
    gate = ApprovalGate()
    action = {"type": "deploy", "version": "1.0.0"}
    gate.authorize(action, "authorized-reviewer-demo")
    assert gate.permitted(action)
    assert not gate.permitted({**action, "version": "2.0.0"})
    print("Approval is action-specific")

8. Real-world design exercise

You are building a multi-agent collaboration capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Build a deterministic reviewer handoff. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Duplicating agent roles without benefit. Mitigation: make this condition explicit in a test or a runtime policy.
  • Allowing shared artifacts to overwrite each other. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In supervisor multi-agent orchestration, what happens between “Research worker” and “Final synthesis”, and what must be checked?

Follow the labeled arrows in the diagram: Research worker hands a defined result through the intermediate stages toward Final synthesis. For this topic, explicitly guard against duplicating agent roles without benefit.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.
