LangGraph orchestration

Learning outcome: Represent workflows as nodes, edges and state reducers

1. What is it?

LangGraph represents execution as a graph with named nodes, typed state and transitions. A node reads state and returns an update. Conditional edges encode deterministic branching.

2. Why does it matter?

Prefer graphs when checkpointing, human intervention and branch visibility are requirements.

Concrete scenario: Route a reviewable workflow based on node output. The figure below names the actual components and shows how information moves among them.

3. Key concepts and vocabulary

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

5. Step-by-step algorithm

  1. START: Process the start stage, and pass its defined output to the next node.
  2. Plan node: Process the plan node stage, and pass its defined output to the next node.
  3. Execute node: Process the execute node stage, and pass its defined output to the next node.
  4. Review node: Process the review node stage, and pass its defined output to the next node.
  5. Approve?: Process the approve? stage, and pass its defined output to the next node.
  6. END: Emit a result only after verifying the stated conditions.

6. Runnable Python lesson

This module links to 08_langgraph.py. Some modules reuse an earlier example intentionally: revisit it and identify which concept is newly relevant. The downloadable file is in the examples/ folder.

Run locally: python examples/08_langgraph.py from the extracted project root. Examples using provider libraries also need the dependencies and credentials explained in Setup.
"""Requires: pip install langgraph. No model or API key needed."""
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    task: str
    approved: bool
    result: str

def classify(state: State):
    return {"approved": state["task"].startswith("read:")}

def route(state: State) -> str:
    return "execute" if state["approved"] else "deny"

def execute(state: State):
    return {"result": "Completed safe read-only demo"}

def deny(state: State):
    return {"result": "Denied: requires approval"}

builder = StateGraph(State)
builder.add_node("classify", classify)
builder.add_node("execute", execute)
builder.add_node("deny", deny)
builder.add_edge(START, "classify")
builder.add_conditional_edges("classify", route, {"execute": "execute", "deny": "deny"})
builder.add_edge("execute", END)
builder.add_edge("deny", END)
graph = builder.compile()

if __name__ == "__main__":
    print(graph.invoke({"task": "read: status", "approved": False, "result": ""}))

7. Code walkthrough

Code-reading checklist for LangGraph state machine: locate the input contract, identify where the “Plan node” responsibility appears, and check how output reaches “END”. The reusable example may demonstrate only one part of the architecture; do not mistake it for a complete implementation.

8. Real-world design exercise

You are building a langgraph orchestration capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Build a graph with conditional branches. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Mutating shared state without reducer understanding. Mitigation: make this condition explicit in a test or a runtime policy.
  • Using unconditional edges for conditional behavior. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In langgraph state machine, what happens between “Plan node” and “END”, and what must be checked?

Follow the labeled arrows in the diagram: Plan node hands a defined result through the intermediate stages toward END. For this topic, explicitly guard against mutating shared state without reducer understanding.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.
