Inside an agent runtime

Learning outcome: Construct a controller with model, tool dispatcher, validator and budget

1. What is it?

The runtime, not the LLM, must enforce which tools exist, budgets, safety policies, and terminal conditions. The model may suggest a call, but trusted application code validates and executes it.

2. Why does it matter?

Keep model I/O, tool execution, policy decisions, and storage in separate modules so each can be tested.

Concrete scenario: Trace a tool call from policy to state storage. The figure below names the actual components and shows how information moves among them.

3. Key concepts and vocabulary

ConceptExplanation
Controllerowns the execution loop
Registrymaps tool names to callable implementations
Executorinvokes only permitted tools
Trace storerecords observable events

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

5. Step-by-step algorithm

  1. Inbound request: Process the inbound request stage, and pass its defined output to the next node.
  2. Policy controller: Process the policy controller stage, and pass its defined output to the next node.
  3. Model adapter: Process the model adapter stage, and pass its defined output to the next node.
  4. Tool registry: Process the tool registry stage, and pass its defined output to the next node.
  5. Tool executor: Process the tool executor stage, and pass its defined output to the next node.
  6. State + trace store: Emit a result only after verifying the stated conditions.

6. Runnable Python lesson

This module links to 02_tool_registry.py. Some modules reuse an earlier example intentionally: revisit it and identify which concept is newly relevant. The downloadable file is in the examples/ folder.

Run locally: python examples/02_tool_registry.py from the extracted project root. Examples using provider libraries also need the dependencies and credentials explained in Setup.
"""Validated tool registry using only Python standard library."""
from dataclasses import dataclass
from collections.abc import Callable

@dataclass(frozen=True)
class ToolSpec:
    name: str
    fn: Callable[[int, int], int]

def multiply(a: int, b: int) -> int:
    return a * b

REGISTRY = {"multiply": ToolSpec("multiply", multiply)}

def execute(name: str, arguments: dict) -> int:
    if name not in REGISTRY:
        raise PermissionError("Unknown or prohibited tool")
    if set(arguments) != {"a", "b"} or any(type(v) is not int for v in arguments.values()):
        raise ValueError("Arguments must be integer a and b")
    return REGISTRY[name].fn(**arguments)

if __name__ == "__main__":
    print(execute("multiply", {"a": 6, "b": 7}))

8. Real-world design exercise

You are building a inside an agent runtime capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Write a lightweight typed agent runtime. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Embedding authorization inside model prompts. Mitigation: make this condition explicit in a test or a runtime policy.
  • Mixing model messages with trusted state. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In agent runtime component architecture, what happens between “Policy controller” and “State + trace store”, and what must be checked?

Follow the labeled arrows in the diagram: Policy controller hands a defined result through the intermediate stages toward State + trace store. For this topic, explicitly guard against embedding authorization inside model prompts.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.
