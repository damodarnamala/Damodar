Human approval gates

Learning outcome: Pause risky writes until authorization is granted

1. What is it?

A human approval gate freezes a proposed action, shows the precise intended side effect, and resumes only after a valid authorized decision. An approval must be linked to the exact action version.

2. Why does it matter?

Do not allow old approvals to authorize revised production commands.

Concrete scenario: Review a risky write before execution. The figure below names the actual components and shows how information moves among them.

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

5. Step-by-step algorithm

  1. Proposed action: Process the proposed action stage, and pass its defined output to the next node.
  2. Risk classifier: Process the risk classifier stage, and pass its defined output to the next node.
  3. Pause + persist: Process the pause + persist stage, and pass its defined output to the next node.
  4. Human review: Process the human review stage, and pass its defined output to the next node.
  5. Approve?: Process the approve? stage, and pass its defined output to the next node.
  6. Execute or reject: Emit a result only after verifying the stated conditions.

"""Illustrates approval tied to an exact proposed action digest."""
import hashlib
import json

def digest(action: dict) -> str:
    data = json.dumps(action, sort_keys=True, separators=(",", ":")).encode()
    return hashlib.sha256(data).hexdigest()

class ApprovalGate:
    def __init__(self):
        self.approved = set()

    def authorize(self, action: dict, reviewer: str):
        if not reviewer:
            raise ValueError("Reviewer identity required")
        self.approved.add(digest(action))

    def permitted(self, action: dict) -> bool:
        return digest(action) in self.approved

if __name__ == "__main__":
    gate = ApprovalGate()
    action = {"type": "deploy", "version": "1.0.0"}
    gate.authorize(action, "authorized-reviewer-demo")
    assert gate.permitted(action)
    assert not gate.permitted({**action, "version": "2.0.0"})
    print("Approval is action-specific")

8. Real-world design exercise

You are building a human approval gates capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Build an approval-gated deployment simulation. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Interpreting silence as consent. Mitigation: make this condition explicit in a test or a runtime policy.
  • Executing before recording approval. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In human approval activity diagram, what happens between “Risk classifier” and “Execute or reject”, and what must be checked?

Follow the labeled arrows in the diagram: Risk classifier hands a defined result through the intermediate stages toward Execute or reject. For this topic, explicitly guard against interpreting silence as consent.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.
