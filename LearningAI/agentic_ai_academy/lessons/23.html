Testing and evaluation

Learning outcome: Measure correctness, safety, and completion quality

1. What is it?

Evaluation measures both final answers and the path taken to get them. Track tool choice, prohibited actions, task success, cost, latency and failure recovery separately.

2. Why does it matter?

Create deterministic fixtures and replayable test scenarios.

Concrete scenario: Gate releases against repeatable checks. The figure below names the actual components and shows how information moves among them.

3. Key concepts and vocabulary

ConceptExplanation
Golden taskfixed representative evaluation case
Trajectorysequence of agent/tool actions
Contract testverifies interface assumptions
Regressionpreviously working behavior that broke

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

5. Step-by-step algorithm

  1. Unit tool tests: Process the unit tool tests stage, and pass its defined output to the next node.
  2. Contract checks: Process the contract checks stage, and pass its defined output to the next node.
  3. Mock-agent scenarios: Process the mock-agent scenarios stage, and pass its defined output to the next node.
  4. Golden tasks: Process the golden tasks stage, and pass its defined output to the next node.
  5. Security probes: Process the security probes stage, and pass its defined output to the next node.
  6. Release gate: Emit a result only after verifying the stated conditions.

"""Run: python -m unittest discover -s examples -p 'test_*.py'"""
import unittest
from importlib.machinery import SourceFileLoader
from pathlib import Path

MODULES = Path(__file__).parent
planner = SourceFileLoader("planner", str(MODULES / "04_planner.py")).load_module()

class TestPlanner(unittest.TestCase):
    def test_order(self):
        order = planner.schedule({"build": ["plan"], "plan": []})
        self.assertEqual(order, ["plan", "build"])

    def test_cycle(self):
        with self.assertRaises(ValueError):
            planner.schedule({"a": ["b"], "b": ["a"]})

if __name__ == "__main__":
    unittest.main()

8. Real-world design exercise

You are building a testing and evaluation capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Create pytest tests for the agent loop. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Testing only final prose outputs. Mitigation: make this condition explicit in a test or a runtime policy.
  • Using live paid models in every unit test. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In agent evaluation testing pyramid, what happens between “Contract checks” and “Release gate”, and what must be checked?

Follow the labeled arrows in the diagram: Contract checks hands a defined result through the intermediate stages toward Release gate. For this topic, explicitly guard against testing only final prose outputs.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.

Hands-on assignment

Modify 12_tests.py to log each step as a dictionary containing step, action, status and elapsed_ms. Then write tests for one success case and one rejection case.

Interview angle

Design interview: You need to gate releases against repeatable checks. Defend the boundaries between unit tool tests and release gate, describe how to handle “testing only final prose outputs”, and identify a measurable acceptance test.
