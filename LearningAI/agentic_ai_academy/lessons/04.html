Agent algorithms

Learning outcome: Implement ReAct, plan/execute, reflection and stopping conditions

1. What is it?

ReAct alternates between selecting an action and observing its result. Plan-and-Execute creates a preliminary plan first. Reflection adds an evaluation pass, but a critique is not proof of correctness.

2. Why does it matter?

Always cap iterations and require independent validators for important facts or side effects.

Concrete scenario: Choose tool, observe evidence, then stop or retry. The figure below names the actual components and shows how information moves among them.

3. Key concepts and vocabulary

4. Topic-specific architecture and execution flow

Every branch is controlled by application code. A model can recommend an action, but it does not automatically gain permission to perform that action. Record observations and check the terminal condition after every step.

5. Step-by-step algorithm

  1. Question: Process the question stage, and pass its defined output to the next node.
  2. Model proposes action: Process the model proposes action stage, and pass its defined output to the next node.
  3. Execute tool: Process the execute tool stage, and pass its defined output to the next node.
  4. Observation: Process the observation stage, and pass its defined output to the next node.
  5. Validated answer?: Process the validated answer? stage, and pass its defined output to the next node.
  6. Stop or retry: Emit a result only after verifying the stated conditions.

6. Runnable Python lesson

This module links to 01_agent_loop.py. Some modules reuse an earlier example intentionally: revisit it and identify which concept is newly relevant. The downloadable file is in the examples/ folder.

Run locally: python examples/01_agent_loop.py from the extracted project root. Examples using provider libraries also need the dependencies and credentials explained in Setup.
"""No API key needed. A deterministic agent-like tool loop."""
from dataclasses import dataclass

@dataclass
class Action:
    name: str
    a: float = 0
    b: float = 0

def add(a: float, b: float) -> float:
    return a + b

def run(goal: str, max_steps: int = 3) -> str:
    tools = {"add": add}
    history = []
    for _ in range(max_steps):
        if not history:
            action = Action("add", 12, 30) if goal == "add" else Action("final")
        else:
            return f"Result: {history[-1]}"
        if action.name == "final":
            return "Unsupported request"
        if action.name not in tools:
            raise ValueError("Not allowed")
        history.append(tools[action.name](action.a, action.b))
    raise RuntimeError("Step limit")

if __name__ == "__main__":
    assert run("add") == "Result: 42"
    print(run("add"))

8. Real-world design exercise

You are building a agent algorithms capability for an enterprise assistant. It must complete a user task while preserving authorization, explicit failure states, and observable results.

Build task: Compare two algorithm traces. Start with one valid scenario, one invalid input and one failure case. Add an explicit max-step or timeout condition and document whether the workflow has side effects.

9. Common mistakes and troubleshooting

  • Confusing reflection with independent testing. Mitigation: make this condition explicit in a test or a runtime policy.
  • No cycle limit for planning or tool use. Mitigation: make this condition explicit in a test or a runtime policy.

10. Practice and knowledge check

In react loop with bounded termination, what happens between “Model proposes action” and “Stop or retry”, and what must be checked?

Follow the labeled arrows in the diagram: Model proposes action hands a defined result through the intermediate stages toward Stop or retry. For this topic, explicitly guard against confusing reflection with independent testing.

How do you stop an agent from looping forever?

Use a maximum step count, time limit, cost budget and explicit terminal condition.

How do you prove that the result is correct?

Use independent deterministic validation, trusted source evidence, tests and human approval as appropriate.
